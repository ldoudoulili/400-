# 400电话记录 安卓App — 使用与打包说明

## 一、App 功能介绍

本 App 是一款纯离线运行的安卓应用，专门用于记录 400 电话维修来电。

- **纯离线运行**：所有数据均存储在手机本地（localStorage），无需联网，不依赖任何服务器。
- **一键选通话记录**：点击「从通话记录选择」，可直接从手机系统通话记录中挑选刚接到的来电，号码和来电时间自动填入，无需手动输入。
- **完整记录字段**：支持填写事件描述、处理结论，并可标记是否需要继续跟进。
- **按日期查看**：默认显示当天记录，可切换日期查看历史记录。
- **搜索与筛选**：支持按关键词搜索，可一键筛选「仅看需跟进」的记录。
- **导出 CSV**：可将全部记录导出为 CSV 文件，方便在电脑上用 Excel/WPS 整理归档。

## 二、首次使用权限设置

安装后首次打开 App，功能很简单，但有一个关键权限需要授予：

1. 安装完成后打开 App。
2. 点击首页的「**从通话记录选择**」按钮时，系统会弹出权限请求弹窗，请求**读取通话记录**权限。
3. 点击「允许」即可。

### 各品牌手机手动开启路径

如果权限被拒绝，或弹窗未出现，可手动到系统设置中开启：

- **小米手机（MIUI）**：设置 → 应用设置 → 应用管理 → 400电话记录 → 权限管理 → 通话记录 → 允许
- **华为手机（HarmonyOS/EMUI）**：设置 → 应用和服务 → 权限管理 → 400电话记录 → 通话记录 → 允许
- **OPPO 手机（ColorOS）**：设置 → 应用管理 → 400电话记录 → 权限 → 通话记录 → 允许
- **vivo 手机（OriginOS）**：设置 → 应用管理 → 400电话记录 → 权限 → 通话记录 → 允许

### 注意事项

- 如果权限被拒绝，点击「从通话记录选择」按钮时 App 会提示你去设置中手动开启。
- 安卓 11（API 30）及以上系统，「读取通话记录」属于特殊权限，部分品牌可能需要在设置中额外找到「读取通话记录」开关并手动允许。
- 未授权通话记录权限时，App 的其他功能（手动添加记录、查看历史、导出）仍可正常使用。

## 三、日常使用流程

接到维修电话后，按以下步骤操作：

1. 打开「400电话记录」App。
2. 点击「**从通话记录选择**」按钮。
3. 在弹出的通话记录列表中找到刚接到的电话，点击该条记录。
4. App 会自动将**号码**和**来电时间**填入表单。
5. 填写「事件描述」（简述客户遇到的问题）。
6. 填写「处理结论」（当场给出的解答或处理方案）。
7. 如果需要后续跟进（例如要回电、要上门、要查资料），勾选「**需要继续跟进**」。
8. 点击「**添加记录**」按钮保存。
9. 保存后，列表默认显示当天所有记录，最新一条排在最前。

> 小技巧：如果通话记录列表里没找到对应来电，也可以直接手动填写号码和时间后添加。

## 四、数据导出

- 点击 App 内的「**导出全部记录**」按钮，可将所有记录一次性导出为 CSV 文件。
- 导出的 CSV 文件保存在手机的**下载目录**（Download 文件夹）中，文件名类似 `calllog_YYYYMMDD_HHMMSS.csv`。
- 将手机连接电脑，或通过微信/QQ 传到电脑，用 **Excel 或 WPS** 即可打开查看和编辑。
- 建议每周导出一次 CSV 作为备份。

## 五、打包 APK 流程（GitHub Actions 方式）

本项目已配置 GitHub Actions 自动打包工作流，推送到 GitHub 后会自动构建 Debug APK。

### 1. 在 GitHub 上创建仓库

登录 GitHub，新建一个仓库，例如命名为 `400电话维修记录`。

### 2. 将本地项目推送到 GitHub

打开 PowerShell / 命令行，执行：

```bash
cd D:\Project\GITEE\400电话维修记录
git init
git add .
git commit -m "init: 400电话维修记录 电脑版 + 安卓App"
git branch -M main
git remote add origin https://github.com/你的用户名/400电话维修记录.git
git push -u origin main
```

> 请将上面命令中的「你的用户名」替换为你实际的 GitHub 用户名。

### 3. 查看 Actions 构建进度

推送成功后，打开 GitHub 仓库页面，点击顶部的「**Actions**」标签页，即可看到名为「Build Android APK」的工作流正在运行。

构建过程大约需要 3～5 分钟（首次构建较慢，后续有缓存会快一些）。

### 4. 下载 APK

构建成功后：

1. 点击进入该次构建的运行详情页。
2. 拉到页面底部的「**Artifacts**」区域。
3. 点击 `400电话记录-debug` 下载，得到一个压缩包。
4. 解压后即可获得 `400电话记录-debug.apk` 文件。

### 5. 安装到手机

- 将 APK 文件传到手机（微信/QQ/数据线均可）。
- 在手机上点击 APK 安装。
- 首次安装时，系统可能提示「**允许安装未知来源应用**」，按提示前往设置开启后返回安装即可。

## 六、本地打包（可选，需安装 Android SDK）

如果不想用 GitHub Actions，也可以在本地直接构建 APK。

### 前置环境

- 已安装 **Android Studio**（自带 Android SDK 和 Gradle）。
- 已安装 **Node.js 18+**。

### 构建命令

```bash
cd 安卓App
npm install
npx cap sync android
cd android
gradlew.bat assembleDebug
```

### APK 输出路径

构建完成后，Debug APK 位于：

```
安卓App\android\app\build\outputs\apk\debug\app-debug.apk
```

将该文件传到手机即可安装。

## 七、注意事项

1. **数据安全**：所有数据仅存储在手机本地（localStorage），**卸载 App 会清空全部数据**。请定期使用「导出 CSV」功能备份。
2. **不与电脑版互通**：本安卓 App 是独立运行的离线版，**不会**与电脑版的 `data.json` 同步数据。
3. **Debug 签名**：当前自动打包产出的是 Debug 签名 APK，可直接安装使用，无需额外配置签名。
4. **发布到应用商店**：如果未来需要上架应用商店，需要在 `安卓App/android/app/build.gradle` 中配置 Release 签名（keystore），并将构建命令改为 `assembleRelease`。
5. **更新版本**：每次 push 到 main/master 分支都会自动构建新的 APK，旧版本不会被覆盖，可在 Actions 历史中随时下载。
